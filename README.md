# Tools

A collection of web tools in one app, with a Go (Gin) backend and a React (Vite + TypeScript) frontend.

## Tech Stack

| Part     | Stack                                   |
| -------- | --------------------------------------- |
| Backend  | Go 1.26, Gin, go-qrcode (QR generation), gozxing (QR decoding) |
| Database | PostgreSQL, pgx (driver), sqlx (queries), goose (migrations) |
| Frontend | React 19, React Router 8, Vite 8, TypeScript 6, oxlint |
| Delivery | Docker (one image: the Go server also serves the built frontend), GitHub Actions, Docker Hub |

## Tools

Each tool lives at `/tools/<slug>` and is listed on the home page and in the sidebar.

### QR Code Generator (`/tools/qr-code`)

Type text or a URL, pick a size (128–1024 px) and an error-correction level (L, M, Q, H), and download the result as a PNG. The image is generated by the backend (`POST /api/qr`).

### QR Code Reader (`/tools/qr-reader`)

Read a QR code two ways:

- **Upload:** pick or drag-and-drop a PNG, JPEG or GIF (up to 10 MB).
- **Camera:** scan live; the page samples frames from the camera and stops at the first QR code found.

The decoded text can be copied, or opened if it's a link. Decoding happens on the backend (`POST /api/qr/decode`).

### Alarm (`/tools/alarm`)

A live clock showing the **server's** time (with its timezone), plus alarms set against that clock:

- **Add alarms:** pick a time (HH:MM in the server's timezone), an optional label and optional repeat weekdays. With no weekdays an alarm rings once and switches itself off.
- **Manage:** toggle alarms on or off and delete them. The list is sorted by next ring and shows "rings in 2h 5m". Alarms are saved in this browser (`localStorage`).
- **Ringing:** a pop-up with Dismiss and Snooze (5 min), a beep (Web Audio, no audio files) and, if you allow it, a browser notification.
- **Good to know:** alarms only ring while the page is open (a background tab is fine). If the server clock can't be reached, the page says so and offers a retry instead of falling back to your device's time. The time comes from `GET /api/time`, re-synced every minute and when the tab becomes visible again.

### Timer (`/tools/timer`)

A countdown set with hours, minutes and seconds or the 1, 5, 10 and 25 minute presets. Start, pause, resume and reset it; a progress ring shows what's left and the tab title shows the remaining time while it runs. It counts down to an end timestamp, so a throttled background tab doesn't drift. When it hits zero it beeps and sends a notification (if allowed). It uses your device's clock and only runs while the page is open.

### Calendar (`/tools/calendar`)

A month calendar with every Indonesian **public holiday** (hari libur nasional) and **cuti bersama** marked, as set by the government's SKB 3 Menteri:

- **Tanggal merah:** Sundays and public holidays have red dates; public holidays get a red cell, cuti bersama a dashed blue one, and today a blue dot.
- **Browse:** move by month or jump back to today. Click a day to see what it is; the month's holidays are listed below with how many days away they are.
- **Coverage:** 2025, 2026 and 2027. Other years show a note instead of holidays. Data comes from the backend (`GET /api/holidays`); Islamic holiday dates can still shift with the official moon sighting.

### Pomodoro (`/tools/pomodoro`)

A focus timer that works in rounds: focus, then a short break, with a long break after every few focus sessions (25 / 5 / 15 minutes and every 4 rounds by default):

- **Cycle:** a progress ring, dots for the round you're in, and Start, Pause, Resume, Reset and Skip. When a phase ends the next one is lined up (or starts by itself if you turn on auto-start).
- **Settings:** change the lengths, the long-break interval and auto-start. They're saved in this browser (`localStorage`).
- **Label:** say what you're working on for a focus session (optional).
- **Alerts:** the tab title shows the time left and the phase, and a phase ending beeps and sends a notification (if allowed). It counts down to an end timestamp, so a throttled background tab doesn't drift, and it only runs while the page is open.
- **Today:** every finished phase is logged through the API (skipped or reset ones aren't), and the page lists today's sessions with the focus count and total focus time. Sessions are saved in the database, so they're still there after a server restart. If the server can't be reached the timer keeps working and the page offers a retry.

### Stopwatch (`/tools/stopwatch`)

A stopwatch that reads to the hundredth of a second:

- **Controls:** Start, Pause, Resume, Reset and Lap. Keyboard shortcuts: `Space` start / pause, `L` lap, `R` reset (ignored while typing in a field).
- **Laps:** a table with each lap's time and the running total, newest first, with the fastest and slowest lap highlighted once there are two or more.
- **Accuracy:** it measures from `performance.now()` timestamps, so a throttled background tab doesn't drift, and it only runs while the page is open. The tab title shows the elapsed time while it runs.
- **Saved runs:** give a run an optional label and save it once it's paused. The page lists recent runs (label, total, laps, when) and lets you delete them. Runs are kept in the server's memory, so they reset when the server restarts. If the server can't be reached the stopwatch keeps working and the list offers a retry.

### Color Picker (`/tools/color-picker`)

Pick a color and see everything about it:

- **Picker:** a saturation/brightness square and a hue slider (mouse, touch or arrow keys), plus a hex field that checks what you type. Browsers that support it also get a "Pick from screen" eyedropper.
- **From an image:** drop, pick or paste (Ctrl/Cmd+V) an image, then click or tap any spot to take its color; a zoomed loupe shows the pixels and hex under the cursor, and the arrow keys plus Enter work too. The image's main colors are listed as swatches. Everything happens in the browser: the image is never uploaded.
- **Info:** the nearest CSS color name ("≈" when it isn't exact), HEX, RGB, HSL, HSV and CMYK values with copy buttons, and contrast against white and black with WCAG AA/AAA pass badges and a text preview. This comes from the backend (`GET /api/colors`) and updates shortly after you stop moving.
- **Shades and harmonies:** complementary, analogous, triadic, split complementary and tetradic colors, and nine shades. Click any swatch to make it the current color.
- **Saved colors:** save the current color, click a saved one to load it, or remove it. They're kept in this browser (`localStorage`). If the server can't be reached the picker still works and the info panel offers a retry.

### Unit Converter (`/tools/unit-converter`)

Convert between units in 10 categories: length, mass, temperature, volume (US customary), area, speed, time, data (SI `kB` and binary `KiB`), pressure and energy.

- **Convert:** pick a category, type a value, choose the from and to units (or swap them). The result is shown large with a copy button, and the value in every unit of the category is listed below. Click a row to make it the target unit.
- **Remembers:** the last category and each category's unit pair are saved in this browser (`localStorage`).
- **Good to know:** conversions use exact definitional factors (e.g. 1 in = 0.0254 m, 1 lb = 0.45359237 kg). Temperatures below absolute zero are rejected. Conversion happens on the backend (`GET /api/units`, `GET /api/units/convert`), and if the server can't be reached the page offers a retry.

## API

All routes are under `/api`. Errors are returned as `{"error": "<message>"}`.

| Method | Path             | Request                                                                 | Response |
| ------ | ---------------- | ----------------------------------------------------------------------- | -------- |
| GET    | `/api/health`    | –                                                                       | `200` `{"status": "ok", "database": "ok"}`; `503` `{"status": "error", "database": "unreachable"}` when the database doesn't answer a ping |
| GET    | `/api/time`      | –                                                                       | `200` `{"unixMs": int, "iso": string, "timezone": string, "utcOffsetSeconds": int}` (server clock and local zone); `Cache-Control: no-store` |
| GET    | `/api/holidays` | Query `year`?: 1–9999 (default: current year in the server's timezone) | `200` `{"year": int, "holidays": [{"date": "YYYY-MM-DD", "name": string, "type": "national"\|"collective_leave"}], "availableYears": [int]}`; a year without data has `holidays: []`; `400` on an invalid year |
| GET    | `/api/colors`   | Query `hex`: 3 or 6 hex digits, optional `#` (`%23`), case-insensitive | `200` `{"hex": "#RRGGBB", "rgb", "hsl", "hsv", "cmyk", "name": string, "exactName": bool, "contrast": {"white", "black", "bestText"}, "harmonies": {"complementary", "analogous", "triadic", "splitComplementary", "tetradic"}, "shades": [9 hex]}` (nearest CSS color name, WCAG 2 contrast ratios, hue-rotation harmonies, shades at lightness 90 to 10); `400` on a missing or invalid `hex`; `Cache-Control: public, max-age=86400` |
| GET    | `/api/units`    | –                                                                       | `200` `{"categories": [{"id": string, "name": string, "units": [{"id": string, "name": string, "symbol": string}]}]}` (10 categories, in display order); `Cache-Control: public, max-age=86400` |
| GET    | `/api/units/convert` | Query `category`, `from` (a unit id of that category), `value` (finite, \|value\| ≤ 1e15) | `200` `{"category": string, "from": string, "value": number, "results": [{"unit": string, "value": number}]}` (the value in every unit of the category, unrounded); `400` on a missing or unknown category or unit, an invalid value, or a temperature below absolute zero; `Cache-Control: public, max-age=86400` |
| POST   | `/api/pomodoro/sessions` | JSON `{"kind": "focus"\|"short_break"\|"long_break", "durationSeconds": 1–14400, "label"?: string (up to 100 characters), "completedAt"?: RFC3339 (default: now)}` | `201` `{"id": string, "kind": string, "durationSeconds": int, "label": string, "completedAt": string}`; `400` on invalid input (including `completedAt` more than 1 minute in the future); `500` if the database fails; sessions are saved in the `pomodoro_sessions` table |
| GET    | `/api/pomodoro/sessions` | Query `date`?: `YYYY-MM-DD` (default: today in the server's timezone) | `200` `{"date": "YYYY-MM-DD", "sessions": [session], "focusCount": int, "focusSeconds": int}` for sessions completed that day in the server's timezone, oldest first; `400` on an invalid date; `Cache-Control: no-store` |
| POST   | `/api/stopwatch/sessions` | JSON `{"label"?: string (up to 100 characters), "elapsedMs": 1–86400000, "laps"?: [int] (lap durations in ms, each ≥ 1, at most 1000, sum ≤ elapsedMs), "completedAt"?: RFC3339 (default: now)}` | `201` `{"id": string, "label": string, "elapsedMs": int, "laps": [int], "completedAt": string}`; `400` on invalid input (including `completedAt` more than 1 minute in the future); sessions are kept in memory (newest 1,000) |
| GET    | `/api/stopwatch/sessions` | Query `limit`?: 1–200 (default 50) | `200` `{"sessions": [session]}` newest first (by `completedAt`); `400` on an invalid limit; `Cache-Control: no-store` |
| DELETE | `/api/stopwatch/sessions/:id` | – | `204` on success; `404` if the session does not exist |
| POST   | `/api/qr`        | JSON `{"content": string, "size"?: 128–1024 (default 256), "level"?: "L"\|"M"\|"Q"\|"H" (default "M")}`; content up to 2048 bytes | `200` `image/png`; `400` on invalid input |
| POST   | `/api/qr/decode` | `multipart/form-data` with an `image` file (PNG, JPEG or GIF, up to 10 MB) | `200` `{"content": string}`; `400` on missing/oversized/unsupported image; `422` if no QR code is found |

## Project Structure

```

docker-compose.yml    # The image plus a local PostgreSQL
.github/workflows/    # ci.yml: tests on pull requests; release.yml: image build, push and deploy on v* tags

  cmd/server/         # HTTP server entry point: loads config, connects to the DB, applies migrations, graceful shutdown
  cmd/migrate/        # Migration CLI: status, up, down, create
  migrations/         # Schema migrations (goose SQL files, embedded in the binary); see its README
  internal/config/    # Settings from env vars / backend/.env
  internal/database/  # PostgreSQL connection pool and migration runner
  internal/router/    # Route registration (/api group) and serving the built frontend (STATIC_DIR)
  internal/handler/   # Request handlers + tests

  src/api/            # Typed API clients (fetch wrappers)

  src/theme/          # Light/dark theme hook and toggle button
  src/pages/          # Home (tool grid), tool page wrapper, 404
  src/tools/          # registry.ts (list of tools) + one folder per tool
  src/tools/shared/   # Used by alarm and timer: server clock hook, beep + notifications, ring dialog

tasks/
  plans/              # Per-task plans
  lessons/            # Lessons learned, by domain
```

## Getting Started

### Backend

```bash
cd backend
cp .env.example .env     # then fill in the PostgreSQL settings (DB_HOST, DB_USER, DB_PASSWORD, DB_NAME, ...)
./run.sh                 # stops anything on PORT (default 8080), then runs go run ./cmd/server
go test ./...
TEST_DATABASE_URL='postgres://user:pass@localhost:5432/tools_test?sslmode=disable' go test ./...   # also runs the database tests
```

The database tests are skipped unless `TEST_DATABASE_URL` is set. Point it at a throwaway database, never your real one: the tests empty the tables they use.

The server needs the database: it stops with a message if a required setting is missing or PostgreSQL can't be reached, and applies any pending migrations before it starts serving. Variables set in the shell override `.env`.

Every schema change is a SQL file in `backend/migrations/` (see [its README](backend/migrations/README.md)):

```bash
go run ./cmd/migrate create add_something   # new migrations/NNNNN_add_something.sql
go run ./cmd/migrate status                 # applied / pending
go run ./cmd/migrate up                     # apply pending
go run ./cmd/migrate down                   # roll back the latest
```

### Frontend

```bash
cd frontend
npm install
npm run dev              # Vite dev server
npm run build            # type-check + production build
npm run lint
```

### Docker

The `Dockerfile` builds one image: the frontend is built with Node, the backend into a static Go binary, and the server serves both (`STATIC_DIR=/app/public`, with `index.html` for client-side routes such as `/tools/qr-code`). The database settings are passed when the container runs, never baked into the image.

```bash
docker compose up --build    # the app plus a local PostgreSQL, at http://localhost:8080
docker build -t tools .      # just the image
docker run -p 8080:8080 -e DB_HOST=... -e DB_USER=... -e DB_PASSWORD=... -e DB_NAME=... tools
```

The image sets `TZ=Asia/Jakarta`, because "today", alarms and the holidays default year use the server's timezone; pass `-e TZ=...` to change it. Migrations run when the server starts; `/app/migrate` is in the image too (`docker run ... tools /app/migrate status`).

### CI and releases

Two workflows run on GitHub's free runners:

| Workflow | Runs on | What it does |
| -------- | ------- | ------------ |
| `.github/workflows/ci.yml` | Pull requests to `main` | Backend `go vet` + tests (with a PostgreSQL service, so the database tests run) and frontend lint + build, side by side. No image. |
| `.github/workflows/release.yml` | Tags `v*` (e.g. `v1.2.0`) | Builds the image and pushes it as `1.2.0`, `1.2` and `latest`, then deploys it: SSH into the server, pull that version, `docker compose up` and wait for the health check. No tests: they ran on the pull request. |

Merging to `main` publishes nothing; only a tag does. Images go to Docker Hub as `<username>/tools`. Set this up once under Settings → Secrets and variables → Actions: a repository **variable** `DOCKERHUB_USERNAME` and a **secret** `DOCKERHUB_TOKEN` (a Docker Hub access token with Read & Write).

To release: `git tag v1.0.0 && git push origin v1.0.0` (from `main`, after the merge).

The deploy needs one-time setup on the server and in GitHub (an SSH key, a `production` environment with its secrets, and a `.env` on the server); see [deploy/README.md](deploy/README.md).

### Adding a tool

1. Build the page under `frontend/src/tools/<slug>/` with a default-exported component.
2. Add an entry to `TOOLS` in `frontend/src/tools/registry.ts` (slug, name, description, category, icon, keywords, lazy component).

The sidebar, home grid, search and `/tools/<slug>` route pick it up automatically.

In dev, Vite proxies `/api` to `http://localhost:8080`, so start the backend alongside it and call the API with relative URLs (e.g. `fetch('/api/qr')`).
