# Tools

A collection of web tools in one app, with a Go (Gin) backend and a React (Vite + TypeScript) frontend.

## Tech Stack

| Part     | Stack                                   |
| -------- | --------------------------------------- |
| Backend  | Go 1.26, Gin, go-qrcode (QR generation), gozxing (QR decoding) |
| Database | PostgreSQL, pgx (driver), sqlx (queries), goose (migrations) |
| Frontend | React 19, React Router 8, Vite 8, TypeScript 6, oxlint |
| Delivery | Docker (one image: the Go server also serves the built frontend), GitHub Actions, Docker Hub |

## Tools

Each tool lives at `/tools/<slug>` and is listed on the home page and in the sidebar.

### QR Code Generator (`/tools/qr-code`)

Type text or a URL, pick a size (128–1024 px) and an error-correction level (L, M, Q, H), and download the result as a PNG. The image is generated by the backend (`POST /api/qr`).

### QR Code Reader (`/tools/qr-reader`)

Read a QR code two ways:

- **Upload:** pick or drag-and-drop a PNG, JPEG or GIF (up to 10 MB).
- **Camera:** scan live; the page samples frames from the camera and stops at the first QR code found.

The decoded text can be copied, or opened if it's a link. Decoding happens on the backend (`POST /api/qr/decode`).

### Alarm (`/tools/alarm`)

A live clock showing the **server's** time (with its timezone), plus alarms set against that clock:

- **Add alarms:** pick a time (HH:MM in the server's timezone), an optional label and optional repeat weekdays. With no weekdays an alarm rings once and switches itself off.
- **Manage:** toggle alarms on or off and delete them. The list is sorted by next ring and shows "rings in 2h 5m". Alarms are saved in this browser (`localStorage`).
- **Ringing:** a pop-up with Dismiss and Snooze (5 min), a beep (Web Audio, no audio files) and, if you allow it, a browser notification.
- **Good to know:** alarms only ring while the page is open (a background tab is fine). If the server clock can't be reached, the page says so and offers a retry instead of falling back to your device's time. The time comes from `GET /api/time`, re-synced every minute and when the tab becomes visible again.

### Timer (`/tools/timer`)

A countdown set with hours, minutes and seconds or the 1, 5, 10 and 25 minute presets. Start, pause, resume and reset it; a progress ring shows what's left and the tab title shows the remaining time while it runs. It counts down to an end timestamp, so a throttled background tab doesn't drift. When it hits zero it beeps and sends a notification (if allowed). It uses your device's clock and only runs while the page is open.

### Calendar (`/tools/calendar`)

A month calendar with every Indonesian **public holiday** (hari libur nasional) and **cuti bersama** marked, as set by the government's SKB 3 Menteri:

- **Tanggal merah:** Sundays and public holidays have red dates; public holidays get a red cell, cuti bersama a dashed blue one, and today a blue dot.
- **Browse:** move by month or jump back to today. Click a day to see what it is; the month's holidays are listed below with how many days away they are.
- **Coverage:** 2025, 2026 and 2027. Other years show a note instead of holidays. Data comes from the backend (`GET /api/holidays`); Islamic holiday dates can still shift with the official moon sighting.

### Date Calculator (`/tools/date-calculator`)

Three calculators on tabs, all worked out in the browser:

- **Add / subtract:** a start date plus or minus years, months, weeks and days (or quick picks like +10 days, +5 weeks, +1 month). The answer is a tear-off calendar page with the full date, how far it is from today, its ISO week, day of the year and quarter, and the holiday's name if it lands on one. Month math keeps the day of the month, or stops at the month's last day (31 Jan + 1 month = 28/29 Feb) and says so. Switch to **working days** to count only Monday–Friday, optionally skipping Indonesian public holidays and cuti bersama (from `GET /api/holidays`); the holidays it passes over are listed.
- **Between dates:** the days from one date to another, with an option to count the end day too, shown as years-months-days, weeks and days, whole months, hours, minutes and seconds, plus a bar splitting them into working days, holidays and weekend days.
- **Convert:** a duration in seconds, minutes, hours, days, weeks, months, years or decades in every other unit, plus a breakdown (1 year = 52 weeks and 1 day). A year is 365, 365.2425 (average, with leap years) or 366 days; a month is a twelfth of a year. Click any unit to convert from it, or jump to "what date is 1 year from today?".

Holidays are known for the years the backend has data for (2025–2027); elsewhere only weekends are skipped, and the page says so. The open tab and the holiday choice are remembered on the device.

### Pomodoro (`/tools/pomodoro`)

A focus timer that works in rounds: focus, then a short break, with a long break after every few focus sessions (25 / 5 / 15 minutes and every 4 rounds by default):

- **Cycle:** a progress ring, dots for the round you're in, and Start, Pause, Resume, Reset and Skip. When a phase ends the next one is lined up (or starts by itself if you turn on auto-start).
- **Settings:** change the lengths, the long-break interval and auto-start. They're saved in this browser (`localStorage`).
- **Label:** say what you're working on for a focus session (optional).
- **Alerts:** the tab title shows the time left and the phase, and a phase ending beeps and sends a notification (if allowed). It counts down to an end timestamp, so a throttled background tab doesn't drift, and it only runs while the page is open.
- **Today:** every finished phase is logged through the API (skipped or reset ones aren't), and the page lists today's sessions with the focus count and total focus time. Sessions are saved in the database, so they're still there after a server restart. If the server can't be reached the timer keeps working and the page offers a retry.

### Stopwatch (`/tools/stopwatch`)

A stopwatch that reads to the hundredth of a second:

- **Controls:** Start, Pause, Resume, Reset and Lap. Keyboard shortcuts: `Space` start / pause, `L` lap, `R` reset (ignored while typing in a field).
- **Laps:** a table with each lap's time and the running total, newest first, with the fastest and slowest lap highlighted once there are two or more.
- **Accuracy:** it measures from `performance.now()` timestamps, so a throttled background tab doesn't drift, and it only runs while the page is open. The tab title shows the elapsed time while it runs.
- **Saved runs:** give a run an optional label and save it once it's paused. The page lists recent runs (label, total, laps, when) and lets you delete them. Runs are kept in the server's memory, so they reset when the server restarts. If the server can't be reached the stopwatch keeps working and the list offers a retry.

### Color Picker (`/tools/color-picker`)

Pick a color and see everything about it:

- **Picker:** a saturation/brightness square and a hue slider (mouse, touch or arrow keys), plus a hex field that checks what you type. Browsers that support it also get a "Pick from screen" eyedropper.
- **From an image:** drop, pick or paste (Ctrl/Cmd+V) an image, then click or tap any spot to take its color; a zoomed loupe shows the pixels and hex under the cursor, and the arrow keys plus Enter work too. The image's main colors are listed as swatches. Everything happens in the browser: the image is never uploaded.
- **Info:** the nearest CSS color name ("≈" when it isn't exact), HEX, RGB, HSL, HSV and CMYK values with copy buttons, and contrast against white and black with WCAG AA/AAA pass badges and a text preview. This comes from the backend (`GET /api/colors`) and updates shortly after you stop moving.
- **Shades and harmonies:** complementary, analogous, triadic, split complementary and tetradic colors, and nine shades. Click any swatch to make it the current color.
- **Saved colors:** save the current color, click a saved one to load it, or remove it. They're kept in this browser (`localStorage`). If the server can't be reached the picker still works and the info panel offers a retry.

### Unit Converter (`/tools/unit-converter`)

Convert between units in 10 categories: length, mass, temperature, volume (US customary), area, speed, time, data (SI `kB` and binary `KiB`), pressure and energy.

- **Convert:** pick a category from the icon tiles, type a value in the blue **From** panel and pick units from the chips; the red **To** panel shows the result large with a copy button and a plain sentence ("3.7 meter is 12.14 foot"). The round button between them swaps the units, and ×10, ÷10 and ± nudge the value.
- **Put it in perspective:** the value is compared with everyday things (bananas, buses, Olympic pools, HD movies…), with the closest match drawn as a row of emoji. Temperatures get a thermometer with freezing, body and boiling marks and a one-line feel ("A warm day.").
- **Every unit:** the value in every unit of the category, each with a log-scale bar showing its size. Click a row to make it the target unit.
- **Remembers:** the last category and each category's unit pair are saved in this browser (`localStorage`).
- **Good to know:** conversions use exact definitional factors (e.g. 1 in = 0.0254 m, 1 lb = 0.45359237 kg). Temperatures below absolute zero are rejected. Conversion happens on the backend (`GET /api/units`, `GET /api/units/convert`), and if the server can't be reached the page offers a retry.

### Lorem Ipsum Generator (`/tools/lorem-ipsum`)

Placeholder text on demand:

- **Pick:** paragraphs (1–50), sentences (1–200) or words (1–2000) with the chips, then type a number or drag the slider. The text updates as you change things.
- **Options:** start with the classic "Lorem ipsum dolor sit amet, consectetur adipiscing elit." (on by default), and show it as plain text or as HTML `<p>` tags.
- **Shuffle:** changing the options keeps the same random seed, so the text just grows or shrinks; **Shuffle the words** picks a new one.
- **Copy:** copies the text in the chosen format; the paragraph, word and character counts are shown above it.
- **Good to know:** the text is generated on the backend (`GET /api/lorem`) from a Latin word list; the same seed and options always give the same text. If the server can't be reached the page offers a retry.

### Word Counter (`/tools/word-counter`)

Count words and more as you type or paste.

- **Counts:** words, characters (with and without spaces), sentences, paragraphs and lines, plus reading time (238 words a minute) and speaking time (130 words a minute). They update live.
- **Smart counting:** "don't", "e-mail" and "3.5" are one word each and lone punctuation like "—" isn't counted; Chinese, Japanese and Thai text is split into words with the browser's `Intl.Segmenter`, and an emoji or accented letter counts as one character.
- **Limit:** keep it under an X post (280 characters), a meta description (160 characters) or your own number of words or characters; the bar turns red and shows how far over you are.
- **Top words:** the eight most used words, optionally skipping common English and Indonesian ones ("the", "and", "yang"…).
- **Good to know:** everything runs in the browser, so the text is never sent to the server. It's kept on this device as a draft, so a reload doesn't lose it; Clear removes it.

### Case Converter (`/tools/case-converter`)

Turn text into any case at once and copy the one you need.

- **For writing:** UPPER CASE, lower case, Title Case, Sentence case, iNVERSE cASE and aLtErNaTiNg cAsE. Title Case keeps small English and Indonesian words ("of", "the", "dan", "di", "yang"…) lowercase unless they start or end a phrase; Sentence case capitalizes each sentence and the word "I".
- **For code:** camelCase, PascalCase, snake_case, CONSTANT_CASE, kebab-case and dot.case. Words are split on spaces, punctuation and case changes, so "XMLHttpRequest", "user_id" and "Hello world" all convert cleanly; each line converts on its own, so a list of names stays a list.
- **Copy or chain:** every result has Copy and "Use this", which puts it back in the box to convert again; **Original case** brings back the text you typed or pasted.
- **Good to know:** everything runs in the browser, so the text is never sent to the server. It's kept on this device as a draft, so a reload doesn't lose it; Clear removes it.

### Base64 Encoder / Decoder (`/tools/base64`)

Turn text or a file into Base64, or Base64 back into text, an image or a file.

- **Encode:** text is encoded as UTF-8, so accents and emoji come back intact. Pick, drop or paste a file or screenshot (up to 5 MB) to encode its bytes, optionally as a `data:` URL for HTML and CSS; images show a thumbnail. Options: URL-safe alphabet (`-` and `_`), padding on or off, and wrapping at 76 characters (email / MIME). The size is shown with how much longer Base64 makes it (about a third).
- **Decode:** spaces and line breaks are ignored, standard and URL-safe Base64 and missing padding are all accepted, and a `data:…;base64,` prefix is stripped. Dropping a `.txt` file decodes the Base64 in it. Bad input gets an error naming the character and where it is.
- **Text or file:** decoded bytes that are text are shown as text; anything else is shown as a file with its size, a guessed type (PNG, JPEG, GIF, WebP, PDF, ZIP), an image preview, the first bytes in hex and a Download button.
- **Separate inputs:** Encode and Decode each keep their own text, so switching modes swaps the input and switching back brings yours back. "Decode it" / "Encode it" put the result into the other mode's input.
- **Wrong mode?** Base64 typed into Encode, or plain text typed into Decode, gets a nudge with a button that moves the text to the other mode.
- **Copy, download or check:** Copy the result, download it as a file, or "Decode it" / "Encode it" to send it back the other way and check the round trip. "Try an example" fills in a sample.
- **How it works:** a fold-out shows your first 3 bytes as bits, cut into four 6-bit groups, each with its number and letter, with the fill bits and `=` padding marked.
- **Good to know:** everything runs in the browser, so nothing is sent to the server. Both inputs and your options are kept on this device; Clear empties the current one.

### JWT Decoder / Encoder (`/tools/jwt`)

Read what's inside a JSON Web Token and check its signature, or build and sign a new one. Two modes at the top, **Decode** and **Encode & sign** (remembered); each keeps its own input while you switch.

- **Colored token:** the token is painted in three colors (header, payload, signature) right in the box you type in, and each part's card wears the same color.
- **Decode:** paste a token; a `Bearer ` prefix, quotes and line breaks are fine. Header fields and payload claims are listed with what they mean (`iss`, `sub`, `aud`, `exp`, `nbf`, `iat`, `jti` and common OpenID ones), times as local dates with "in 40 minutes" / "3 days ago", and a warning when a time looks like milliseconds. Stickers show the algorithm, whether it's expired or not valid yet (ticking every second, with an optional clock leeway of 30 s, 1 min or 5 min, as servers allow; remembered) and the signature result. A **lifetime bar** shows where now falls between `nbf` / `iat` and `exp`. Errors say which part is broken; an encrypted JWE is recognized (only its header is readable); `alg: none` gets a warning.
- **Heads-up list:** common mistakes are called out under the token: `alg: none`, **algorithm confusion** (an HS* token checked with a public key as its secret, worded more strongly when it actually verifies), `jku` / `x5u` key URLs in the header, path or quote characters in `kid`, lifetimes over 30 days, `iat` in the future, and secret-looking payload fields (`password`, `client_secret`, `api_key`, `nik`, `pin`…), since the payload isn't encrypted.
- **Verify the signature:** HS256/384/512 with a secret (as text or Base64), RS*, PS*, ES256/384/512 and EdDSA (Ed25519) with a public key as PEM, a certificate, a JWK or a JWKS (picked by the token's `kid`); a private key works too. A secret shorter than RFC 7518 asks for gets a note, and a DER-encoded ECDSA signature is pointed out. Secrets are multi-line boxes, so a pasted key keeps its exact bytes.
- **Encode & sign:** pick an algorithm from the chips, edit the header and payload JSON (`alg` follows the chip), and set `iat`, `exp` (in 15 min, 1 h, 1 day or 7 days), `nbf` or a random `jti` with one click. HS* takes a secret (or a random one; a public key pasted as the secret gets a warning); the others take a PKCS#8 PEM or JWK private key, or **Generate key pair** makes one and shows the public key to copy. The token updates as you type.
- **Round trips:** "Decode it" opens the new token in Decode with the matching key, so it verifies; "Edit & re-sign" takes a decoded token's header, payload and secret into Encode.
- **Good to know:** everything runs in the browser with Web Crypto, so tokens and keys are never sent to the server, and they aren't saved (only the mode, algorithm and leeway are remembered). In high-contrast (forced colors) mode the token shows in plain system colors.

### SVG Viewer (`/tools/svg-viewer`)

Look at an SVG up close, repaint its colors, pit two versions against each other and take it away as a PNG or a React component. Two modes at the top, **Studio** and **A vs B** (remembered).

- **Open:** drop an `.svg` on the board, open a file (up to 5 MB), or paste SVG code or a file anywhere on the page; "Paste code" and the **Code** button open the code panel to type in. "Try an example" fills in a sample. A missing `xmlns` or `xmlns:xlink` (common in SVG copied out of HTML) is added, and an `<svg>` wrapped in other markup is found. Broken code gets the parser's error with line and column on the board, while the last version that worked stays on screen.
- **Studio artboard:** a big board with the file name taped on top. A zoom dock (buttons, mouse wheel or trackpad pinch around the cursor, keys `+` `-`, `0` to fit, `1` for actual size; drag or arrow keys to move) and a background dock (checkerboard, white, black or a color you pick) float on it.
- **Paint pots (recolor):** every color the SVG uses sits in a tray under the art, with how often it's used. Hover a pot and that color flashes pink on the art, so you can see where it is. Click one to open the mixer: pick a new color (color picker, any CSS color typed in, or `currentColor` for icons) and the art tries it out live; **Repaint** changes every use at once, in `fill` / `stroke` / gradient stops and the other color attributes, `style="…"` and `<style>` sheets (`#fff` and `#ffffff` count as one color, `!important` is kept). The rest of the code stays as it was; Undo is in the toast.
- **Details:** size in px (hover for where it comes from: width / height with any unit, the viewBox, or the 300 × 150 default), viewBox, element count (hover for the tags), file size and lines. A notes sticker opens what's worth knowing: scripts, event handlers, external files, embedded bitmaps, `<foreignObject>`, `currentColor`, and what was fixed to show it.
- **Take it with you:** PNG at 1×, 2×, 4× or a width you type (up to 8192 px), transparent or on the board color, from the caret next to the PNG sticker; the `.svg` file; copy the code, a `data:` URL (percent-encoded, not Base64) or a CSS `background-image`. Every copy and save says so in a toast.
- **Code panel:** slides in beside the board (below it on smaller screens) with two tabs. **SVG code** to edit, with Format (indented) and Minify (no comments, `<metadata>` or extra whitespace; text in `<text>`, `<style>` and the like is left as is), both with Undo. **React** turns the SVG into a component (or just the JSX): `class` → `className`, `stroke-width` → `strokeWidth`, `xlink:href` → `href`, `style="…"` → a style object, `<style>` as a template literal, text escaped for JSX. Comments, `<metadata>`, scripts, event handlers and editor attributes (Inkscape and the like) are left out, with a note. Options: name (from the file name), TypeScript, pass props through (`{...props}`), size with CSS (no width / height). Copy it or download a `.tsx` / `.jsx`.
- **A vs B:** two contender cards (thumbnail, name, size; drop a file on one, open a file, or edit its code) with a VS badge between them that swaps A and B. A is the Studio SVG; B has its own draft, and "Copy A" starts it as a copy. One board to compare them on: **Swipe** (B over A, with a handle you drag on the art or move with the arrow keys), **Side by side** (zoom and pan move together) or **Difference** (pixels that differ in red over a faded A, with a sticker saying how much differs). Under it, chips for what differs (size, viewBox, elements, file size, colors only in A struck through → only in B), and the code changes folded behind their `+N −M` count: a side-by-side line diff, formatted first so only real changes show (or as typed), with the changed part of each line marked and long unchanged stretches folded. Pasting anywhere fills the side being edited, else the empty one.
- **Good to know:** the art is drawn as an image, so scripts in the SVG never run and nothing is fetched. Everything runs in the browser; the code, B, and your choices are kept on this device.

### Spin Wheel (`/tools/spin-wheel`)

Let a wheel decide: who goes first, what's for lunch, the raffle winner.

- **Entries:** one per line (up to 100); write one twice to double its chance. Shuffle, sort A–Z or clear them; they're saved on this device.
- **Spin:** click the wheel or press Spin. It turns a few times and slows to a stop under the pointer, then shows the pick, with **Remove** to take it off the wheel (handy for drawing names one by one).
- **Recent picks:** the last 10 results.

### Dice Roller (`/tools/dice`)

- **Dice:** 1–10 dice of one type: d4, d6, d8, d10, d12, d20 or d100. A d6 shows pips; the others show the number.
- **Roll:** the dice tumble and land, and the total is shown as a sum (e.g. "3 + 5 + 2 = 10"), plus an optional modifier (−99 to +99, like the +2 in 1d20+2). A die that rolls its highest number is outlined red.
- **Hold:** after a roll, click a die to keep its number on the next roll; Release all lets them go.
- **Recent rolls:** the last 10, with notation, each die and the total.

### Coin Flip (`/tools/coin-flip`)

- **Flip:** click the coin or press Flip for a 3D flip; Flip 10× and Flip 100× do a batch at once and show the split.
- **Tally:** heads vs tails with percentages and a split bar, the current and longest streak, and the last 40 flips as little coins. Reset starts over.
- **Name the sides:** rename heads and tails (e.g. "Yes" / "No", or two names).

All three run in the browser and use the crypto random generator (`crypto.getRandomValues`, without modulo bias), so every result is equally likely. Animations are skipped if your system asks for reduced motion.

## API

All routes are under `/api`. Errors are returned as `{"error": "<message>"}`.

| Method | Path             | Request                                                                 | Response |
| ------ | ---------------- | ----------------------------------------------------------------------- | -------- |
| GET    | `/api/health`    | –                                                                       | `200` `{"status": "ok", "database": "ok"}`; `503` `{"status": "error", "database": "unreachable"}` when the database doesn't answer a ping |
| GET    | `/api/time`      | –                                                                       | `200` `{"unixMs": int, "iso": string, "timezone": string, "utcOffsetSeconds": int}` (server clock and local zone); `Cache-Control: no-store` |
| GET    | `/api/holidays` | Query `year`?: 1–9999 (default: current year in the server's timezone) | `200` `{"year": int, "holidays": [{"date": "YYYY-MM-DD", "name": string, "type": "national"\|"collective_leave"}], "availableYears": [int]}`; a year without data has `holidays: []`; `400` on an invalid year |
| GET    | `/api/colors`   | Query `hex`: 3 or 6 hex digits, optional `#` (`%23`), case-insensitive | `200` `{"hex": "#RRGGBB", "rgb", "hsl", "hsv", "cmyk", "name": string, "exactName": bool, "contrast": {"white", "black", "bestText"}, "harmonies": {"complementary", "analogous", "triadic", "splitComplementary", "tetradic"}, "shades": [9 hex]}` (nearest CSS color name, WCAG 2 contrast ratios, hue-rotation harmonies, shades at lightness 90 to 10); `400` on a missing or invalid `hex`; `Cache-Control: public, max-age=86400` |
| GET    | `/api/units`    | –                                                                       | `200` `{"categories": [{"id": string, "name": string, "units": [{"id": string, "name": string, "symbol": string}]}]}` (10 categories, in display order); `Cache-Control: public, max-age=86400` |
| GET    | `/api/units/convert` | Query `category`, `from` (a unit id of that category), `value` (finite, \|value\| ≤ 1e15) | `200` `{"category": string, "from": string, "value": number, "results": [{"unit": string, "value": number}]}` (the value in every unit of the category, unrounded); `400` on a missing or unknown category or unit, an invalid value, or a temperature below absolute zero; `Cache-Control: public, max-age=86400` |
| GET    | `/api/lorem`    | Query `unit`?: `paragraphs` (default) \| `sentences` \| `words`; `count`?: 1–50 / 1–200 / 1–2000 per unit (default 3); `startWithLorem`?: `true` (default) \| `false`; `seed`?: 0–4294967295 (default: random) | `200` `{"unit": string, "count": int, "seed": int, "paragraphs": [string], "words": int}` (sentences and words come back as one paragraph; the same seed and options give the same text); `400` on an invalid unit, count, flag or seed; `Cache-Control: public, max-age=86400` with a seed, `no-store` without |
| POST   | `/api/pomodoro/sessions` | JSON `{"kind": "focus"\|"short_break"\|"long_break", "durationSeconds": 1–14400, "label"?: string (up to 100 characters), "completedAt"?: RFC3339 (default: now)}` | `201` `{"id": string, "kind": string, "durationSeconds": int, "label": string, "completedAt": string}`; `400` on invalid input (including `completedAt` more than 1 minute in the future); `500` if the database fails; sessions are saved in the `pomodoro_sessions` table |
| GET    | `/api/pomodoro/sessions` | Query `date`?: `YYYY-MM-DD` (default: today in the server's timezone) | `200` `{"date": "YYYY-MM-DD", "sessions": [session], "focusCount": int, "focusSeconds": int}` for sessions completed that day in the server's timezone, oldest first; `400` on an invalid date; `Cache-Control: no-store` |
| POST   | `/api/stopwatch/sessions` | JSON `{"label"?: string (up to 100 characters), "elapsedMs": 1–86400000, "laps"?: [int] (lap durations in ms, each ≥ 1, at most 1000, sum ≤ elapsedMs), "completedAt"?: RFC3339 (default: now)}` | `201` `{"id": string, "label": string, "elapsedMs": int, "laps": [int], "completedAt": string}`; `400` on invalid input (including `completedAt` more than 1 minute in the future); sessions are kept in memory (newest 1,000) |
| GET    | `/api/stopwatch/sessions` | Query `limit`?: 1–200 (default 50) | `200` `{"sessions": [session]}` newest first (by `completedAt`); `400` on an invalid limit; `Cache-Control: no-store` |
| DELETE | `/api/stopwatch/sessions/:id` | – | `204` on success; `404` if the session does not exist |
| POST   | `/api/qr`        | JSON `{"content": string, "size"?: 128–1024 (default 256), "level"?: "L"\|"M"\|"Q"\|"H" (default "M")}`; content up to 2048 bytes | `200` `image/png`; `400` on invalid input |
| POST   | `/api/qr/decode` | `multipart/form-data` with an `image` file (PNG, JPEG or GIF, up to 10 MB) | `200` `{"content": string}`; `400` on missing/oversized/unsupported image; `422` if no QR code is found |

## Project Structure

```
Dockerfile            # One image: builds the frontend and backend, serves both from the Go server
docker-compose.yml    # The image plus a local PostgreSQL
.github/workflows/    # ci.yml: tests on pull requests; release.yml: image build, push and deploy on v* tags
deploy/               # Server side: compose.prod.yml (behind Traefik) and deploy.sh; see its README
backend/
  cmd/server/         # HTTP server entry point: loads config, connects to the DB, applies migrations, graceful shutdown
  cmd/migrate/        # Migration CLI: status, up, down, create
  migrations/         # Schema migrations (goose SQL files, embedded in the binary); see its README
  internal/config/    # Settings from env vars / backend/.env
  internal/database/  # PostgreSQL connection pool and migration runner
  internal/router/    # Route registration (/api group) and serving the built frontend (STATIC_DIR)
```

## Getting Started

### Backend

```bash
cd backend
cp .env.example .env     # then fill in the PostgreSQL settings (DB_HOST, DB_USER, DB_PASSWORD, DB_NAME, ...)
./run.sh                 # stops anything on PORT (default 8080), then runs go run ./cmd/server
go test ./...
TEST_DATABASE_URL='postgres://user:pass@localhost:5432/tools_test?sslmode=disable' go test ./...   # also runs the database tests
```

The database tests are skipped unless `TEST_DATABASE_URL` is set. Point it at a throwaway database, never your real one: the tests empty the tables they use.

The server needs the database: it stops with a message if a required setting is missing or PostgreSQL can't be reached, and applies any pending migrations before it starts serving. Variables set in the shell override `.env`.

Every schema change is a SQL file in `backend/migrations/` (see [its README](backend/migrations/README.md)):

```bash
go run ./cmd/migrate create add_something   # new migrations/NNNNN_add_something.sql
go run ./cmd/migrate status                 # applied / pending
go run ./cmd/migrate up                     # apply pending
go run ./cmd/migrate down                   # roll back the latest
```

### Frontend

```bash
cd frontend
npm install
npm run dev              # Vite dev server
npm run build            # type-check + production build
npm run lint
```

### Docker

The `Dockerfile` builds one image: the frontend is built with Node, the backend into a static Go binary, and the server serves both (`STATIC_DIR=/app/public`, with `index.html` for client-side routes such as `/tools/qr-code`). The database settings are passed when the container runs, never baked into the image.

```bash
docker compose up --build    # the app plus a local PostgreSQL, at http://localhost:8080
docker build -t tools .      # just the image
docker run -p 8080:8080 -e DB_HOST=... -e DB_USER=... -e DB_PASSWORD=... -e DB_NAME=... tools
```

The image sets `TZ=Asia/Jakarta`, because "today", alarms and the holidays default year use the server's timezone; pass `-e TZ=...` to change it. Migrations run when the server starts; `/app/migrate` is in the image too (`docker run ... tools /app/migrate status`).

### CI and releases

Two workflows run on GitHub's free runners:

| Workflow | Runs on | What it does |
| -------- | ------- | ------------ |
| `.github/workflows/ci.yml` | Pull requests to `main` | Backend `go vet` + tests (with a PostgreSQL service, so the database tests run) and frontend lint + build, side by side. No image. |
| `.github/workflows/release.yml` | Tags `v*` (e.g. `v1.2.0`) | Builds the image and pushes it as `1.2.0`, `1.2` and `latest`, then deploys it: SSH into the server, pull that version, `docker compose up` (Traefik routes the domain to it) and wait for the health check. No tests: they ran on the pull request. |

Merging to `main` publishes nothing; only a tag does. Images go to Docker Hub as `<username>/tools`. Set this up once under Settings → Secrets and variables → Actions: a repository **variable** `DOCKERHUB_USERNAME` and a **secret** `DOCKERHUB_TOKEN` (a Docker Hub access token with Read & Write).

To release: `git tag v1.0.0 && git push origin v1.0.0` (from `main`, after the merge).

The deploy needs one-time setup on the server and in GitHub (an SSH key, a `production` environment with its secrets, and a `.env` on the server); see [deploy/README.md](deploy/README.md).

### Adding a tool

1. Build the page under `frontend/src/tools/<slug>/` with a default-exported component.
2. Add an entry to `TOOLS` in `frontend/src/tools/registry.ts` (slug, name, description, category, icon, keywords, lazy component).

The sidebar, home grid, search and `/tools/<slug>` route pick it up automatically.

In dev, Vite proxies `/api` to `http://localhost:8080`, so start the backend alongside it and call the API with relative URLs (e.g. `fetch('/api/qr')`).
